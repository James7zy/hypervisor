# HV-004（第一刀）— VM 暂停/恢复 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development（或 executing-plans）。每 Task 后跑 gate，绿了才 commit。

**Goal:** Service VM 能暂停/恢复另一个 VM，暂停真的让它不再被调度，恢复后继续；状态可查。

**Architecture:** `paused` 是调度判据（pick 丢弃 + kick 强制换下），不是"停下 guest"；
hypercall 只改状态并发 kick，异步生效。纯逻辑在 `common/vm` 与 `common/sched`，host 可测。

**Spec:** [2026-11-08-hv004-vm-pause-design.md](../specs/2026-11-08-hv004-vm-pause-design.md)（F1–F6）。

## Global Constraints

- 不动 `struct vcpu`/`struct percpu` 的 asm 可见前缀；`check_offsets` 必须过。
- `HC_VM_PAUSE/RESUME` 只允许 Service VM（表项 `roles`），参数 `x1 = vmid`。
- 暂停自己 → `HC_EINVAL`；重复暂停/未暂停恢复 → `HC_EBUSY`。
- 既有 12 场景的 expect 只允许**追加**行（`hcall.txt`），其它文件零改动。
- 环境：`PATH=/tmp/wrapbin:$PATH`、`LD_LIBRARY_PATH=/tmp/tc/usr/lib/x86_64-linux-gnu:/tmp/tc/usr/lib`、`CROSS_COMPILE=aarch64-linux-gnu-`；改头文件先 `make clean`。

## Review Focus

| # | 失败模式 | 钉住它的测试 |
|---|---|---|
| 1 | 暂停只改了标志，目标还在跑（异步变永不生效） | `sched_test`：paused VM 的 vCPU 不被选中；`hcall` 场景：VM1 观察到 >1 s 的 `CNTPCT` 空洞 |
| 2 | 恢复后 vCPU 永远回不来（丢队列） | `sched_test`：resume 后重新入队并被选中；`hcall` 场景 VM1 恢复后继续打印 |
| 3 | 非 Service 能暂停他人 | host 分发测试 + `hcall` 场景 VM1 → `HC_EPERM` |
| 4 | 暂停把 BLOCKED 的 vCPU 一起唤醒（伪造事件） | `sched_test`：resume 只入队 RUNNABLE，BLOCKED 保持 |

## Task 1: host RED→GREEN（vm + sched + dispatch）

- **RED commit（仅测试）**：`tests/host/sched_test.c` 加暂停/恢复用例；
  `tests/host/hypercall_test.c` 加 PAUSE/RESUME 权限与状态码用例。必须链接/编译失败。
- **GREEN**：
  - `include/vm.h` + `common/vm/vm.c`：`bool paused`；`vm_is_paused()`；`vm_pause()` →
    `0` / `-EALREADY`；`vm_resume()` 同形；`vm_init` 清零。
  - `include/sched.h` + `common/sched/sched.c`：
    `sched_vm_pause(struct vm *)` = `vm_pause()` + 对每个 RUNNING 的 vCPU `cpu_arch_kick(pcpu)`；
    `sched_vm_resume(struct vm *)` = `vm_resume()` + 对每个 RUNNABLE 的 vCPU `sched_enqueue()` + kick；
    `sched_pick()`/`sched_loop()` 弹出 paused VM 的 vCPU 时 `continue`（保持 RUNNABLE、不入队）。
  - `include/hypercall.h` + `common/hypercall/hypercall.c`：`HC_EBUSY -5`、
    `HC_VM_PAUSE`(`0x87000101`)、`HC_VM_RESUME`(`0x87000102`)，表项 `roles = HC_ROLE_SERVICE`；
    `hc_vm_query` 追加 `bit 32 = paused`。
  - `dm/hv_shell.c`：STATE 列 `paused`（6 字符，不改列宽）。
- 验证：`make host-test` 四套全绿。

## Task 2: kick 分支强制换下暂停 VM 的驻留者

- `arch/arm64/irq/irq_handler.c`：kick 分支在 OFF 判断之后、SGI 排空之前插入
  `if (cv && vm_is_paused(cv->owner) && !idle_window) { sched_preempt_request(); hv_restore(); }`
  （与 tick 路径同形，含 idle 窗口门）。
- 验证：`make test` 12 场景仍绿（此刻还没有场景触发暂停，属编译面）。

## Task 3: 扩展 `hcall` 门禁场景

- `tests/svm/cases/hcall.c`：VM0（Service）在既有断言之后：`HC_VM_PAUSE(1)` → 查询
  读到 `paused` 位 → 用 `CNTPCT` 空转 2 s → `HC_VM_RESUME(1)` → 查询 `paused=0`；
  非 Service 的 VM1 在**自己暂停前**尝试 `HC_VM_PAUSE(0)` → 期望 `-2`，并在被暂停/恢复后
  用自己的时间基检查空洞 > 1 s 并打印 `HCALL: vm1 observed pause`。
- `tests/svm/expect/hcall.txt`：**只追加**行。
- 验证：`make test` 12/12；`make test-qemu-hcall` 连跑 5 次稳定。
