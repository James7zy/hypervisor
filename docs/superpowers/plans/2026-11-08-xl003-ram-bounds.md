# XL-003 RAM 边界实施计划

设计：[spec](../specs/2026-11-08-xl003-ram-bounds-design.md)。基线 `40db2d4`。
范围与两工作日时间盒以 spec 为准；实现前须独立复核设计。未跟踪用户文件不触碰。

## T1：等行为提取与 RED

- 查所有 `stage2_init/s2_map` 调用，核对 `vm_configs.c`、板级地址、loader 与链接布局。
- 将初始建表纯逻辑提取到 `arch/arm64/mmu/` 最小源/头，保留寄存器操作在 `stage2.c`；
  同步 ARM 对象列表与 host 编译入口。先保持固定 1 GiB 旧行为，host 既有测试及
  `make test-qemu-s2fault` 通过后提交等行为重构。
- 新增 host 测试编译生产 builder + 真实 Linux/SVM 双 VM 配置，独立遍历全部叶并核对
  配置范围、OA、属性、HV/peer 排除及设备洞。测试不得调用生产自检作为唯一 oracle。
- 单独 RED 提交：记录具体越界映射断言失败，不以链接缺符号代替此次行为 RED。

## T2：精确建表 GREEN

- RAM 改用配置三元组，不取整；保持设备段和 loader 不变。
- RAM 自检检查所有实际叶与授权范围；非法参数及池耗尽走既有失败通道。
- `vm_config.h` 说明三元组语义；板级注释不再要求 1 GiB 对齐。
- QEMU linker 加 HV（含 BSS/stack）不得侵入 SVM backing 的断言；验证实际链接结果。
- `make host-test` GREEN，保留 RED 的全部承重断言；回归静态检查与现有 QEMU gate。

## T3：负向硬件门禁

- 新 SVM 越界访问 case，可用编译参数选择探针，但不引入生产运行时配置选项。
- `test-qemu-s2bounds` 分三次启动（HV 地址、授权结束地址、peer backing IPA），
  每次要求精确 fault、无穿透标记与同核 VM1 完成。
- 最小复用/扩展既有 harness 增加禁止标记断言，默认既有场景行为不变；为该检查留小自检。
- 新目标纳入 `make test`，明确目标数与 QEMU 启动数不同；不修改旧期望来掩盖回归。
- 受控恢复旧 RAM 映射验证测试变红，随后恢复并 clean 重建。

## T4：独立验收与发布

- 研发交回提交、RED/GREEN 原始退出码和日志路径、运行命令、偏离与缺口；不自行 push。
- 测试专家重新 `make host-test`、`make clean && make test`、`make test-linux`，
  新负向门禁重复三轮；`make test-x86-stub` 与四项静态检查，所有变异恢复。
- 父架构师记录新 ADR（旧 RAM 等价裁定局部替代）、报告与当前架构文档最小同步。
- 通过后 fast-forward 合回 `dev`，push `dev:develop`；H-124 评论范围/提交/报告/验证，
  读回确认，不关闭全项。失败则修复并重新独立复核，不带病合入。

## 影响范围清单

生产：`arch/arm64/mmu/stage2.c` 及提取源/头、ARM 对象列表、QEMU linker/board 注释、
`include/vm_config.h`。测试：host builder 测试与 Makefile、SVM case/expect、负向日志检查。
只回归不重排：`vm_arch_init`/`vm_init` 失败通道、loader、guest DTS、SVM 链接地址。
文档：新 spec/plan/ADR/报告及受影响参考说明。新 ARM 逻辑不泄漏进 generic 层。
