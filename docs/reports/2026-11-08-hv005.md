## 3. 架构师关卡②（2026-11-08）：PASS

Review 范围 `57bf8df..9e7f526` 四个提交 + 收尾改动。确认：

- 身份只来自 `current_vcpu()->owner`（全树唯一调用点 `vmexit.c`），参数永不参与身份判定；
  表项 `roles` 与"依赖参数的权限"两处位置都有注释说明理由。
- 既有 ABI 未动：SMCCC base、PSCI `0x84/0xC4` 分支顺序与行为不变；`HC_GUEST_DONE`
  值仍是 `0x87000001` 且仍不返回；`svm_lib.h` 的重复常量已删（generic 为唯一真相源）。
- `hypercall.c` 无 arch 头、`check-arch-boundary` 与 `check_offsets` 通过；
  `dm/hv_shell.c` 改用共用派生态函数后 `vm_list` 输出语义不变（`shell` 场景绿）。
- RED→GREEN 在历史上可见（`115e050` 仅测试 + Makefile 目标，编译失败）。

**对测试专家非阻塞观察的处理（决定，不再挂账）**：

| 观察 | 处理 |
|---|---|
| 表项 `roles` 分支今天零覆盖（两个调用都是 ANY） | 保留——它是 HV-004 第一个 service-only 调用的形状；在 ADR-0022 说明 |
| `caller == NULL` 未防御 | **写成前置条件**（`hypercall.h` 一行），不加运行期检查：只有 arch 入口调用，真为 NULL 是入口 bug，应该崩而不是静默 |
| `EPERM`/`ENODEV` 泄露 VM 个数 | 有意设计（自识别协议依赖），记入 ADR-0022 |
| `HC_GUEST_DONE` 无权限门 | 记入 ADR-0022，触发条件 = 接入真实 guest 时放测试配置门后 |
| 64 位私有段 `0xC7…` 未接、id 按 `u32` 截断 | 记入 ADR-0022 |
| `0xFFFF` 魔数与返回字位定义分处两地 | **改**：`HC_VMID_BITS` 常量，一处定义 |
| `hcall` 场景靠硬编码 100 ms / 800 ms 错峰 | 记录边界（9 次运行全干净；起机变慢到接近 700 ms 时重估） |

## 4. 已知缺口（本片未消除）

- ABI 只有 test-guest 消费者；minor 兼容不承诺，DM 接上后再谈稳定。
- `HC_VM_QUERY` 报派生态，没有 VM 级状态机（HV-004）。
- 没有结构体型参数 / `copy_from_gpa` 语义（第一个需要的调用出现时再加）。
- 权限只有"Service VM（VM0）/ 其他"两档。
- x86 侧只有链接检查：`hypercall.c` 参与链接，但没有 VMCALL 入口。
