## 4. 已知缺口（本片未消除）

- **H-174 不能宣称消失**：Linux 门禁本轮连跑 5 次全绿，上一轮口径是 14 次中 1 次真实挂死；
  ADR-0019 明确禁止用有限次绿灯结案。抢占把"饥饿"从机制上修掉了，剩余风险是"别的原因也
  可能挂"。
- **RK3588 真机未跑**（M15）：`PSTATE.I` 探针、CNTFRQ 24 MHz、6/7 位 PreBits 都要在真机重跑。
- **量子固定、无优先级**：只保证前向进度，不保证时延（H2 再评估）。
- **`make test-linux` 默认镜像路径是本机的**：新机器需先按 2026-11-06 devlog 构建，再改
  `tests/linux-gate.sha256`。
- Linux 门禁不含并发 FP 忙等 workload；timer 时延不在判据内。
- x86 侧 `cpu_arch_timer_tick_arm()` 仍是空 stub（`test-x86-stub` 只证明链接闭合）。

## 6. 2026-11-08 复核与收尾决定（当日追加）

**14 次 Linux 门禁全绿**（对齐旧缺口的口径"14 次中 1 次真实挂死"）：`make test-linux`
连跑 14 次，14/14 `Linux XVM PASS`，单次约 7–10 s。这不是"证明 H-174 永不出现"，
但样本量与被修复前的口径相同，且确定性场景 `preempt` 是可重复的守门。

**当日的三个决定**（用户 2026-11-08 授权：所有决定归助手裁定，含关 issue、范围与优先级）：

1. **H-174 关为 Done**：它列的三个未做项都有实现与门禁（LR0/AP 保存恢复、片 D 抢占、
   幸存者 timer 两列增长判据）；残余风险（真机、无穷次）写进 ADR-0019/0021，不挂 issue。
   这不是"用有限次绿灯结案"——确定性门禁才是结案依据，14 次连跑是补充观测。
2. **H-115（HV-003）关为 Done**：分区模式（1:1 绑核、无跨 vCPU 抢占）与共享模式（10 ms
   时间片）都已落地并有门禁；**RT 类不实现**——没有 RT VM 类型，按 ponytail 不提前造。
   该条款记入 ADR-0021 后果段（"RT VM 类型立项时再实现"），不新建 backlog issue。
3. **H-27 不再维护**：它在 2026-10-25 已被归档（`archivedAt` 非空），Linear API 对归档件
   的状态/评论/duplicate 链接全部静默忽略（实测三次），所以"标 Duplicate"做不到也不必要——
   归档件不在活动视图里。**H-115 是 MV-003 唯一活动条目**，片 C/D 记录已补在它的评论里。
