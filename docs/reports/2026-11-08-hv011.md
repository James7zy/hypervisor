## 3. 架构师关卡②（2026-11-08）：PASS

- 映射 API 是纯描述符算术、无 arch 头（`check-arch-boundary` 通过），arch 侧只做
  `MAIR/VTCR/VTTBR/dsb/tlbi`。
- 初始映射等价比对自检是这次重构真正的安全网：12 个既有场景 + Linux 门禁共同证明 guest
  内存视图未变。
- fault 路径无 `cpu_arch_halt()`；park 用 `VCPU_EV_OFF`，与 `CPU_OFF` 同一条状态机边。
- 建表失败通道（`vm_arch_init` 返回 int）让"池耗尽"变成显式失败而不是静默继续。

## 4. 测试专家的发现与处理（含一处 spec 自身错误）

| # | 发现 | 处理 |
|---|---|---|
| 1 | **spec G3 写错**：Stage-2 不读 `MAIR_EL2`，描述符自带 `MemAttr`；照 spec 改槽序会静默重定 EL2 身份映射类型 | **改 spec**（标注修订 + 原因）；代码保持现状。MAIR 交换未被所跑 QEMU 场景检出；不能推导所有属性错误都不可测。RO/XN 尚需 guest 负向访问测试，真实缓存与设备访问语义待真机验证 |
| 2 | `data_abort_report` 印的是 pCPU 号却标 `vCPU%u` | **修**：改 `current_vcpu()->vcpu_idx`（一行） |
| 3 | `attr` 选择器越界 → 越界读两项数组（ASan `global-buffer-overflow`），描述符静默变 Device-nGnRnE | **修**：`s2_map/s2_protect` 全校验 `attr`（未知位 + 选择器范围），新增 5 条 host 断言 |
| 4 | `pa` 超 48 位被 `D_OA_MASK` 静默截断 | **修**：`pa >= 2^48` → `S2_EINVAL`，新增断言 |
| 5 | `s2_map` 中途 `ENOMEM` 不回滚；`*flush`/`stage2_flush_vm()` 无运行期消费点 | **记**：spec §6 与 ADR-0025 已知限制，触发条件写明（第一个动态映射消费者 = M13） |
| 6 | `s2fault` expect 首行缺 `[hv] ` 前缀 | **修**：与其他 expect 对齐 |

## 5. 已知缺口

- **验证缺口**：现有描述符断言不替代 RO/XN guest 负向访问门禁；真实 cacheability、共享性与设备访问行为待真机复验。
- 保守全刷 TLB；无巨页拆分；RAM 仍静态；fault 不报给 DM；`s2_map` 无回滚。
- `s2fault` 复用 `svm_xvm2` 拓扑，与 xvm2 的 survivor 语义耦合。
